A04 · Organização e segurança

Seu programa precisa de um ambiente reproduzível

Onde no ambiente: Página, caderno e evidência A03.

Ação: Explicar uma divergência anterior e localizar os arquivos iniciais A04.

O que observar: Se a explicação distingue regra, entrada e resultado.

Retome uma previsão e um resultado da A03. Hoje a regra passa a um módulo próprio: o programa apresenta resultados, recusa entradas inválidas e ganha histórico local revisado.

Objetivos

  • Reconhecer o interpretador do ambiente virtual.
  • Separar apresentação e regra em módulos locais.
  • Distinguir exceção esperada de defeito no código.
  • Revisar arquivos e registrar um commit local.

Pré-requisitos e limites

Executar Python na IDE e CLI; compreender funções, condições e retorno da A03. Python, Git e editor precisam estar disponíveis no laboratório. Se faltarem, registre a pendência e solicite apoio.

Usamos textos fictícios e biblioteca padrão. Sem banco, GUI, ORM, instalação externa ou publicação GitHub nesta aula.

Mobiliza os indicadores de código e documentação. A integração e o executável serão construídos em etapas futuras. O domínio de equipamentos continua como contexto didático, sujeito à escolha da turma.

Atividade 1 · Interpretador correto

Crie o ambiente e comprove o isolamento

Onde no ambiente: PowerShell e VS Code na pasta nova de prática.

Ação: Criar .venv, selecionar o interpretador e registrar caminho/prefixos.

O que observar: O executável dentro da pasta virtual e a comparação dos prefixos.

Leia guia de ambiente. Copie somente o conteúdo de inicial/, incluindo .gitignore, para uma pasta nova fora do material e de outros repositórios. Abra essa pasta na IDE. Não inicialize Git na pasta aluno/professor da UC9.

Selecione esse interpretador em Python: Select Interpreter no VS Code. Registre caminho e versão na IDE e CLI. O comando explícito dispensa ativação e alteração da política do PowerShell.

Critério: explicar a comparação de prefixos e demonstrar a execução pelo ambiente. Não há pacote externo a instalar: requirements.txt tem apenas comentários. Não copie .venv para entrega ou para outra máquina; recrie-a. Um ambiente virtual isola pacotes, não é uma barreira de segurança.

Atividade 2 · Separação de responsabilidades

Observe o import antes de alterar a regra

Onde no ambiente: Editor e PowerShell da pasta de prática.

Ação: Executar os exemplos, importar os módulos e desenhar suas dependências.

O que observar: Se importar dispara impressão e onde está a lacuna declarada.

Na pasta de prática, abra app.py e regras.py lado a lado. Identifique quem apresenta os dados e quem devolve o valor. from regras import ler_quantidade importa o módulo local; não existe dependência chamada regras a instalar.

.\.venv\Scripts\python.exe exemplo_excecoes.py
.\.venv\Scripts\python.exe app.py
.\.venv\Scripts\python.exe -c "import regras"
.\.venv\Scripts\python.exe -c "import app"

O exemplo completo converte um texto e recusa outro. O app inicial apresenta cinco PENDENTE porque a função da regra ainda retorna None. Importar regras e app não deve disparar a demonstração. O bloco if __name__ == "__main__" permite executar a demonstração apenas quando app é o programa principal.

Entrega: desenhe a relação app → regras e descreva a responsabilidade dos três arquivos Python no README. Não chame seus arquivos de json.py ou venv.py: nomes locais podem encobrir bibliotecas. Critério: localizar o módulo certo, executar sem falha de import e explicar os efeitos observados. Python desta página é exibido, não executado no navegador.

Arquivo de trabalho · app.py

"""Apresentação: execute este arquivo; implemente a regra no outro módulo."""
from regras import ler_quantidade


def descrever(texto):
    quantidade = ler_quantidade(texto)
    if quantidade is None:
        return "PENDENTE: complete regras.py"
    return f"Quantidade pronta: {quantidade}"


if __name__ == "__main__":
    for texto in ["2", "0", "-1", "abc", "3.5"]:
        try:
            print(repr(texto), "=>", descrever(texto))
        except ValueError:
            print(repr(texto), "=>", "Entrada recusada: informe um inteiro maior que zero.")

Atividade 3 · Exceções específicas

Uma entrada inválida não pode virar quantidade válida

Onde no ambiente: regras.py no editor, app.py executado no PowerShell ou IDE.

Ação: Substituir a lacuna, prever os casos e comparar execução.

O que observar: Diferença entre falha de conversão, violação da regra e defeito de programação.

Implemente ler_quantidade(texto) em regras.py. Contrato: recebe str, devolve um inteiro maior que zero ou levanta ValueError. Não precisa tratar objetos de outros tipos. Não altere o app para fazer os casos parecerem aprovados.

TextoComportamento exigido
'2'Quantidade inteira aceita
'0' e '-1'Recusa pela regra de domínio
'abc' e '3.5'Recusa da conversão para inteiro

Preveja antes de executar. Use o exemplo de conversão como referência de sintaxe, sem copiar uma solução pronta do desafio. Dica de raciocínio: separe o que int consegue converter da condição que o domínio aceita. Investigue também espaços e sinal positivo; conversão de inteiro não equivale a conversão decimal.

.\.venv\Scripts\python.exe app.py

Critério: uma entrada aceita e quatro recusadas, com continuidade do laço. Acrescente um caso válido e um inválido à sua investigação e registre a explicação. Não devolva zero para esconder erro: zero não satisfaz o contrato. Não use except genérico para esconder NameError ou erros de indentação; leia o traceback e corrija a origem.

Atividade 4 · Histórico e entrega

Revise antes de registrar o primeiro commit

Onde no ambiente: PowerShell na pasta nova; README, evidencias.md e formulário.

Ação: Revisar staged, registrar commit local e exportar o trabalho.

O que observar: Ausência de arquivos sensíveis, histórico verificável e pendências descritas.

Leia o guia Git local e use o checklist em dupla. Na pasta nova, execute git rev-parse --show-toplevel antes de git init. Se houver raiz existente, pare e escolha outra pasta; a mensagem de não ser repositório é esperada antes da inicialização.

Com a prática concluída e o README preenchido, adicione explicitamente os seis arquivos do projeto. Confira git diff --cached e identidade autorizada antes de git commit. Não envie .venv, caches, .env ou dados pessoais. Não há remoto ou push nesta aula. O guia detalha os comandos e os cuidados de configuração local.

Critério: explicar o conteúdo staged, mostrar um commit local e status final, sem remoto. Se Git ou identidade estiverem pendentes, registre isso sem declarar a etapa concluída. Registre hash curto e observações em evidencias.md; apresente o histórico local ao professor.

Entrega: os seis arquivos do projeto, evidências e exportação desta página pelo canal da turma. A exportação não inclui arquivos externos nem os envia automaticamente. Não envie .git ou .venv. Exporte antes de recarregar; as escolhas não são restauradas.

Fechamento: que evidência prova qual interpretador executou? Quem decide a regra? Qual erro deve ser tratado? O que exatamente foi registrado? A05 retomará essa organização para introduzir classes, objetos e composição.
