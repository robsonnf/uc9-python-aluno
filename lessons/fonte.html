01 / CONTEXTO

Um problema, uma jornada

Uma equipe controla empréstimos de equipamentos em anotações dispersas. Como saber o que está disponível e evitar registros inconsistentes? Este é um cenário didático; o domínio do projeto da turma será decidido na A02.

Hoje você prepara sua estação, executa um programa e identifica conhecimentos de Python que precisarão de revisão. Banco de dados e telas serão construídos nos próximos encontros.

Ao sair desta aula

  • Distinguir IDE, terminal, shell e interpretador.
  • Executar o mesmo arquivo pela IDE e pelo terminal.
  • Ler tipos, condições, listas e funções.
  • Registrar evidências e uma dúvida para a A02.

Seu ponto de partida

Use o que já sabe sobre variáveis, laços, coleções e funções. Quando algo for novo, anote a dificuldade. O diagnóstico prepara o apoio; não exige domínio de SQL, POO ou interface gráfica.

Indicadores: preparação para I1 (código) e I3 (documentação); visão inicial de I2 (banco) e I4 (executável). Não certifica competência final.

02 / PROCESSO

Onde estamos na esteira?

O trabalho avança por etapas e volta quando aparece uma falha. Explore o percurso: hoje nosso foco é preparar, executar e observar.

  1. Entender

    Necessidade, requisitos e critérios de aceite. O que precisa funcionar?

  2. Preparar

    IDE, Python, terminal e dependências. Qual programa executa meu arquivo?

  3. Construir

    Regras, dados e interface. Qual pequena funcionalidade consigo implementar?

  4. Verificar

    Executar, depurar e testar. O resultado corresponde ao esperado?

  5. Entregar e manter

    Versão, documentação, executável e correções. Outra pessoa consegue usar?

Observe: no terminal, erro de comando pede investigação do ambiente; saída incorreta pede investigação do código. Registrar o problema evita tentar mudanças sem hipótese.

03 / RECONHECER

Cada ferramenta tem uma função

Abra as fichas e compare com o que vê no computador. Depois aponte onde digitaria um comando e onde escreveria seu programa.

IDE / editor · VS Code

Organiza arquivos, edita código e integra execução e depuração. Abra a pasta da atividade; selecione o Python em “Python: Select Interpreter”. Instalar o editor não instala automaticamente o interpretador.

Terminal e shell · PowerShell

Terminal é a janela; PowerShell interpreta comandos. Use Get-Location para ver a pasta e Get-ChildItem para listar arquivos. Caminhos com espaços precisam de aspas.

Interpretador · Python

Executa o arquivo .py. O prompt >>> é o modo interativo Python, não o PowerShell. Digite exit() para sair desse modo antes dos comandos de shell.

CLI · interface por comandos

Em python --version, python é o comando e --version solicita a versão. Em python primeiro_programa.py, o argumento é o arquivo que será executado.

Dependências e histórico · depois desta aula

venv/pip organizam ambientes e pacotes em A04; Git será apresentado em A02; o primeiro commit revisado ocorre em A04. SQLAlchemy entra em A23 e PyInstaller em A28. Hoje não precisamos de pacotes externos.

04 / PRÁTICA GUIADA

Reconheça sua estação de trabalho

Atividade prática 1 · Objetivo: executar o arquivo fornecido nos dois meios e comparar o interpretador. Ferramentas: VS Code, PowerShell e Python. Dados: apenas informações locais do ambiente.

  1. Baixe e extraia o pacote do aluno. Abra a pasta atividades/A01/inicial no VS Code.
  2. No PowerShell dessa pasta, execute Get-Location e Get-ChildItem. Confirme que primeiro_programa.py aparece.
  3. Execute os comandos abaixo, um por vez. Se python não for reconhecido, avise o professor; use py somente se a instalação local tiver esse comando e a versão for a indicada.
  4. No VS Code, selecione o mesmo interpretador e execute o arquivo salvo pelo botão de execução Python.
  5. Compare mensagem, versão e caminho. Registre em evidencias.md o resultado dos dois meios, sem publicar caminhos com seu nome de usuário.
python --version
python -m pip --version
python primeiro_programa.py

Verificação complementar com o professor: python -m tkinter abre uma janela de demonstração; feche-a após observar. Falha nessa verificação é uma pendência de instalação para a futura GUI, não motivo para impedir o diagnóstico por terminal.

Se a estação ainda não estiver pronta

Com orientação e permissões do laboratório, instale Python pela distribuição oficial validada pelo docente, VS Code e a extensão Python da Microsoft. Reabra o terminal e repita a verificação. Em máquina bloqueada, trabalhe em dupla numa estação preparada e registre a pendência. Não altere políticas do sistema para contornar restrições.

Dica de investigação

Compare o nome do arquivo listado, a pasta atual e o caminho exibido pelo programa. Os dois modos estão chamando a mesma instalação?

Concluído quando: o arquivo roda nos dois meios e você explica qual Python foi usado; ou documenta a falha reproduzível e a tentativa acompanhada. O registro distingue sucesso de pendência.

05 / DIAGNÓSTICO

Leia, preveja, execute, explique

Atividade prática 2 · Objetivo: investigar tipos e uma operação simples. Antes de executar leitura.py, anote no papel o resultado previsto e os tipos de cada valor. Rode python leitura.py, compare com a saída e altere somente a entrada de “3” para “5”. Registre o que mudou. Observe o terminal; não é necessário criar banco.

Baixar leitura.py

entrada = "3"
quantidade = int(entrada)
print(quantidade + 2)
print(entrada + "2")
Dica: investigue os tipos

Compare um valor entre aspas com um número. Qual operação cada tipo permite? Se necessário, experimente print(type(entrada)).

Concluído quando: você registra previsão, resultado observado e explicação para cada linha, inclusive após a alteração.

Desafio prático: em diagnostico.py, complete somente a função itens_disponiveis. Receba uma lista de equipamentos e um limite e devolva uma lista com os nomes cuja quantidade seja maior ou igual ao limite, na ordem original. Não altere os dados fornecidos.

Dados sintéticos: Notebook: 3; Projetor: 0; Cabo: 5. O programa testa limite 1, limite 4 e lista vazia. Confira os nomes manualmente a partir da regra; lista vazia deve produzir lista vazia. Execute python diagnostico.py. O arquivo inicial imprime PENDENTE de propósito até a função ser implementada.

Onde observar: retorno da função e linhas do terminal. Se souber, experimente mais um caso com quantidade exatamente igual ao limite. Não precisa instalar biblioteca.

Dica: decomponha a tarefa

Separe três perguntas: como percorrer os registros, como decidir se um registro atende à regra e onde guardar o nome selecionado? Faça uma tabela em papel antes de codificar.

Concluído quando: você apresenta a função, testa os três casos e explica sua lógica. Se ainda não conseguir, entregue a tentativa e indique o ponto em que parou. Extensão: testar limite 0 e explicar o caso de fronteira.
